Two doors, one engine

The same Rust binary serves both the human developer in VS Code and the AI agent over MCP.

💻

VS Code Extension

Syntax highlighting, step autocomplete, diagnostics while you type. Read scripts from the FileMaker clipboard and write them back — all from the editor.

🧠

MCP Server for AI

Any MCP client (Claude, OpenCode, Cursor) can read, validate, inspect, audit, and cross-reference your scripts and schema. The AI reads the same .fmscript files you do.

🔍

Database Inspector

Parse FMSaveAsXML exports into navigable directories: tables, fields with calculations, layouts with triggers, relationships with joins, custom functions, scripts in folders.

⚠️

Reference Audit

Find broken references automatically: dangling Perform Script and Go to Layout targets, relationships pointing at deleted table occurrences, ghost fields on layouts.

🔗

Cross-Reference

who-calls and who-uses-field: trace every caller of a script and every place a field is used — layouts, relationship keys, Set Field steps, calculation mentions.

📝

Plain-text .fmscript

Scripts are plain text files you can version in git, diff, search, and edit with any tool. The format is human-readable and AI-friendly — the same artifact for both.

How to use fm-bridge

For humans with VS Code, and for AI agents over MCP.

📥 Read from FileMaker

Copy script steps in FileMaker (Ctrl+C), then in VS Code:

Ctrl+Shift+P → fm-bridge: Read script from clipboard

Opens a new .fmscript file with the decoded script.

✏️ Edit in VS Code

Edit the .fmscript file. You get:

  • Syntax highlighting — steps, variables, strings, comments
  • Autocomplete — start typing a step name and it suggests the full template
  • Diagnostics — red errors (unknown steps) and yellow warnings (missing layout IDs)
  • Format — switch between inline (matches FM line numbers) and indented (readable)

📤 Write to FileMaker

Save your .fmscript, then:

Ctrl+Shift+P → fm-bridge: Write script to clipboard

Paste in FileMaker's Script Workspace (Ctrl+V).

🔗 Resolve layout IDs

When you write Go to Layout ["SomeName"] without an ID, FM may show "Desconocido". Resolve them:

Ctrl+Shift+P → fm-bridge: Resolve layout IDs from FMSaveAsXML
→ Pick your database export XML → All IDs auto-filled

Or solve it before writing: configure resolve_from in the write command.

🔌 Setup MCP AI

In VS Code, open the Command Palette:

Ctrl+Shift+P → fm-bridge: Set up MCP for an AI agent

Choose your client (Claude Desktop, OpenCode, Cursor) and the extension writes the config. Then restart the client.

📁 Manual MCP config

If you're not using the extension wizard, add this to your client:

Claude Desktop
// claude_desktop_config.json
{
  "mcpServers": {
    "fm-bridge": {
      "command": "~/.cargo/bin/fm-bridge",
      "args": ["mcp"]
    }
  }
}
OpenCode
// opencode.json
{
  "mcp": {
    "fm-bridge": {
      "type": "local",
      "command": ["~/.cargo/bin/fm-bridge", "mcp"],
      "enabled": true
    }
  }
}

Installv0.1.7

Download the .vsix and install in VS Code. No Rust needed.

# 1. Download the latest .vsix
github.com/LucasVaroneW/fm-bridge/releases

# 2. Install in VS Code
code --install-extension fm-bridge.vsix

# 3. Or: Extensions → ... → Install from VSIX

Or build from source: git clone → cargo install --path .

Zero-install for end users

The .vsix bundles the Rust binary inside. Your users double-click the extension — no Rust, no terminal, no package managers. Works on Windows, macOS, and Linux.
