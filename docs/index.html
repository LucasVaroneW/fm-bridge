Two doors, one engine

The same Rust binary serves both the human developer in VS Code and the AI agent over MCP.

💻

VS Code Extension

Syntax highlighting, step autocomplete, diagnostics while you type. Read scripts from the FileMaker clipboard and write them back.

🧠

MCP Server for AI

Any MCP client (Claude, OpenCode, Cursor) can read, validate, inspect, audit, and cross-reference your scripts and schema.

🔍

Database Inspector

Parse FMSaveAsXML exports into navigable directories: tables, fields with calculations, layouts, relationships, custom functions.

⚠️

Reference Audit

Find broken references: dangling Perform Script / Go to Layout, deleted table occurrences, ghost fields on layouts.

🔗

Cross-Reference

who-calls / who-uses-field: trace every caller of a script and every place a field is referenced.

📝

Plain-text .fmscript

Scripts are plain text files you can version in git, diff, search, and edit with any tool.

Your database, analyzed by AI

Export your FileMaker database as XML once. The engine reads it. You or an AI agent can then ask questions that used to take hours of manual checking.

🔎

Find bugs automatically

fm-bridge audit crosses every script against the schema. Finds Perform Script calls to deleted scripts, Go to Layout to missing layouts, orphaned table occurrences, ghost fields. A full scan in seconds.

📊

Understand impact before changing

who-calls lists everything that triggers a script — other scripts, layout triggers, buttons. who-uses-field finds every reference to a field across the entire database.

🤖

Ask an AI to do it

With MCP set up, tell your AI agent: "Audit this database and list every broken reference". It reads the XML, runs the tools, and gives you the list — no manual digging through 500 scripts.

$ fm-bridge audit By_00_Desk.xml
14 issue(s) in By_00_Desk.fmp12:
   2 Perform Script to missing script
   3 Go to Layout to missing layout
   5 Field on layout with no backing table
   4 Relationship using deleted table occurrence

How to use fm-bridge

For humans with VS Code, and for AI agents over MCP.

📥 Read from FileMaker

Copy script steps in FileMaker (Ctrl+C), then in VS Code:

Ctrl+Shift+P → fm-bridge: Read script from clipboard

✏️ Edit in VS Code

  • Syntax highlighting — steps, variables, strings, comments, numbers
  • Autocomplete — start typing a step name, get snippet templates
  • Diagnostics — red errors (unknown steps) and yellow warnings (missing IDs)
  • Format — inline (matches FM line numbers) or indented (readable)

📤 Write to FileMaker

Ctrl+Shift+P → fm-bridge: Write script to clipboard

Paste in FileMaker's Script Workspace (Ctrl+V).

🔗 Resolve layout IDs

When you write Go to Layout ["SomeName"] without an ID:

Ctrl+Shift+P → fm-bridge: Resolve layout IDs from FMSaveAsXML
→ Pick your database export XML → All IDs auto-filled

🔌 Setup MCP AI

In VS Code, open the Command Palette:

Ctrl+Shift+P → fm-bridge: Set up MCP for an AI agent

Choose your client and the extension writes the config. Restart the client.

📁 Manual MCP config

Claude Desktop
// claude_desktop_config.json
{
  "mcpServers": {
    "fm-bridge": {
      "command": "~/.cargo/bin/fm-bridge",
      "args": ["mcp"]
    }
  }
}
OpenCode
// opencode.json
{
  "mcp": {
    "fm-bridge": {
      "type": "local",
      "command": ["~/.cargo/bin/fm-bridge", "mcp"],
      "enabled": true
    }
  }
}

Installv0.1.8

Download the .vsix and install in VS Code. No Rust needed.

# 1. Download the latest .vsix
github.com/LucasVaroneW/fm-bridge/releases/latest

# 2. Install in VS Code
code --install-extension fm-bridge.vsix

# 3. Or: Extensions → ... → Install from VSIX

Zero-install for end users

The .vsix bundles the Rust binary inside. Your users double-click the extension — no Rust, no terminal, no package managers. Works on Windows, macOS, and Linux.
